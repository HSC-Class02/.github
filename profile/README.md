## 프로젝트 목표

1. **책임 있는 AI** — AI 윤리에 중요한 가치를 두며, 프로젝트 참여 학생 모두 UNESCO의 AI 윤리 과정을 수료했습니다.  
   [![AI 윤리에 관한 글로벌 MOOC](https://img.shields.io/badge/AI%20윤리%20MOOC-Coursera-0056D2?logo=coursera&logoColor=white)](https://www.coursera.org/learn/global-mooc-on-the-ethics-of-ai)
2. **기업 데이터 분석** — DART 공시 데이터를 활용해 상장 기업 재무 분석 AI Agent를 만들고 분석 보고서를 작성합니다.
3. **공공 데이터 분석** — 공공 데이터를 활용해 Analytics AI Agent를 만들고 분석 보고서를 작성합니다.

## 소개

HSC-Class02는 기업과 산업에 관한 데이터를 분석하고 프로젝트 결과를 정리하는 학습 공간입니다. 공개 데이터를 수집·정리하고, 재무 분석과 대시보드 등의 결과물로 구현합니다.

각 저장소에는 **프로젝트 목적 · 사용 방법 · 데이터 출처 · 분석 범위와 한계**를 기록해 학습과 협업에 활용합니다.

## 학생 정보 작성

[✏️ 내 정보 작성하기](https://github.com/HSC-Class02/.github/edit/HEAD/profile/README.md)

이 표는 README 문서입니다. 위 링크에서 파일을 수정한 뒤 **Commit changes**로 제출합니다. 쓰기 권한이 없으면 GitHub의 **Fork → Pull Request** 방식으로 변경을 제안해 주세요.

1. **내 행 찾기**: 브라우저 찾기 기능(`Ctrl+F` / `⌘+F`)으로 본인 저장소 이름을 검색합니다.
2. **이름 작성**: 본인 행의 `이름 입력`을 이름으로 바꿉니다. 원하면 `[이름](https://github.com/본인아이디)` 형식으로 GitHub 프로필을 연결합니다.
3. **개인 링크 작성**: `미입력`을 아래 형식의 실제 링크로 바꿉니다. 주소만 바꾸고 표의 구분자 `|`는 유지해 주세요.
4. **미리보기 확인**: Preview에서 표와 링크를 확인한 뒤 제출합니다. 본인 행만 수정해 주세요.
5. **새 프로젝트 추가**: 해당 표의 마지막 행을 복사하고 새 프로젝트 정보를 입력합니다. 공동 프로젝트는 한 행에 참여자 이름을 함께 적을 수 있습니다.

```markdown
| [홍길동](https://github.com/YOUR_GITHUB_ID) | 기업명<br><sub>저장소이름</sub> | <a href="https://github.com/HSC-Class02/YOUR_REPOSITORY" title="Repository 열기"><img src="https://raw.githubusercontent.com/HSC-Class02/.github/main/profile/assets/link-badges/repository-01.svg" alt="Repository 열기" width="36" height="36"></a> | <a href="https://YOUR_DASHBOARD_URL" title="Dashboard 열기"><img src="https://raw.githubusercontent.com/HSC-Class02/.github/main/profile/assets/link-badges/dashboard-02.svg" alt="Dashboard 열기" width="36" height="36"></a> | [Portfolio ↗](https://YOUR_PORTFOLIO_URL) | [LinkedIn ↗](https://www.linkedin.com/in/YOUR_LINKEDIN_ID/) |
```

> 개인 링크는 본인이 공개할 수 있는 주소만 작성합니다. 대시보드가 아직 없으면 `미등록`을 유지하고, 예시 주소를 실제 주소처럼 등록하지 않습니다.

## 프로젝트 이용 안내

1. 관심 있는 저장소를 선택하고 `README`에서 프로젝트 목적과 실행 방법을 확인합니다.
2. 데이터 출처, 수집 기간, 분석 범위와 한계를 확인합니다.
3. 필요한 API 키는 저장소의 **GitHub Actions Secrets**에 등록하고, 코드나 문서에 직접 공개하지 않습니다.
4. 질문이나 개선 의견은 해당 저장소의 **Issues** 또는 **Pull Request**를 이용합니다. 저장소에서 해당 기능이 활성화되어 있는지 먼저 확인해 주세요.

## 함께 지키는 원칙

- **출처 기록** — 데이터와 분석 결과의 출처를 기록합니다.
- **한계 명시** — 확인되지 않은 값은 임의로 채우지 않고, 한계와 누락을 명확히 표시합니다.
- **정보 보호** — API 키, 비밀번호, 개인 정보 등 민감한 정보를 공개 저장소에 올리지 않습니다.
- **책임 있는 활용** — 프로젝트 결과는 학습과 정보 제공을 위한 것이며, 투자 판단 전에는 원자료와 최신 공시를 확인합니다.
